Java Collections Framework

List Interface

  • Ordered collection (insertion order maintained)
  • Allows duplicate elements
  • Provides positional access (index-based)
  • Supports ListIterator for bidirectional traversal
  • Extends Collection interface

ArrayList

  • Resizable array implementation
  • Fast random access (O(1) get/set)
  • Slow insertions/deletions in middle
  • Not synchronized (not thread-safe)
  • Best for frequent read operations

LinkedList

  • D32 Doubly-linked list implementation
  • Fast insertions/deletions at ends
  • Implements both List and Queue/Dequeue
  • Slow random access (O(n))
  • High memory overhead per element

Vector

  • Legacy synchronized ArrayList
  • Thread-safe but slower
  • Grows by 100% when full
  • All methods synchronized
  • Rarely used in modern code

Stack

  • Extends Vector (LIFO)
  • Provides push, pop, peek
  • Synchronized (thread-safe)
  • Legacy class
  • Prefer Deque (ArrayDeque) instead

Set Interface

  • Unordered collection of unique elements
  • No duplicates allowed
  • Does not maintain insertion order (except LinkedHashSet)
  • No index-based access
  • Extends Collection interface

HashSet

  • Hash table based implementation
  • No order guaranteed
  • Fast operations (O(1) average)
  • Allows one null element
  • Best for quick lookup

LinkedHashSet

  • Maintains insertion order
  • Hash table + linked list
  • Slightly slower than HashSet
  • Allows one null element
  • Predictable iteration order

TreeSet

  • Sorted set (natural order or comparator)
  • Red-black tree implementation
  • No null allowed (after Java 7)
  • O(log n) for add/remove/contains
  • NavigableSet features (floor, ceiling etc.)

Queue Interface

  • Designed for holding elements prior to processing
  • Typically FIFO (first-in-first-out)
  • Provides offer, poll, peek operations
  • Extends Collection interface
  • Supports blocking operations in subinterfaces

PriorityQueue

  • Priority heap based
  • Elements ordered by natural order or comparator
  • Not FIFO - smallest/highest priority first
  • O(log n) insert/remove
  • Does not allow null

ArrayDeque

  • Resizable array as double-ended queue
  • Faster than LinkedList and Stack
  • No capacity restrictions
  • Not thread-safe
  • Recommended for Queue and Deque

Map Interface

  • Stores key-value pairs
  • Unique keys, duplicate values allowed
  • Not part of Collection hierarchy
  • No Iterator directly (use keySet/values/entrySet)
  • Allows one null key (except TreeMap)

HashMap

  • Hash table based
  • No order guaranteed
  • Allows One null key and multiple values allow
  • Fast operations (O(1) average)
  • Not synchronized

LinkedHashMap

  • Maintains insertion order
  • Hash table + linked list
  • Slightly slower than HashMap
  • Allows null key/values
  • Useful for LRU cache

TreeMap

  • Red-black tree based
  • Keys sorted (natural or comparator)
  • No null key allowed
  • O(log n) operations
  • NavigableMap features

Hashtable

Synchronized legacy class
  • No null key or values
  • Thread-safe
  • Legacy (prefer ConcurrentHashMap)
  • All methods synchronized
